## Gap identity and idempotency

`gap_key` is deterministic SHA-256 over:

```text
tenant_id
rule_code
rule_version
gap_type
source_identity_hash
affected_entity_type
affected_entity_id
```

`grc_gaps` enforces unique `(tenant_id, gap_key)`.

Same Observation + same rule does not duplicate Gap.

Later Observations confirming the same condition update the same logical Gap with `latest_source_observation_id`, `last_seen`, `severity`, `last_evaluated_at` and status reopen semantics when needed.

## Eligibility

Material deterministic Gap generation requires:

- `observation.is_current = true`
- `observation.observation_type` matches rule input type
- `observation.quality_status != failed`
- Data Trust state is `TRUSTED_WITH_WARNINGS` or `LOW_CONFIDENCE`
- severity is material: `low`, `medium`, `high`, `critical`

Ignored/non-material states include:

```text
INSUFFICIENT_DATA
UNTRUSTED
SOURCE_SCHEMA_INCOMPATIBLE
SOURCE_DATA_INSUFFICIENT
FORMULA_DEPENDENCY_PENDING
FORMULA_VARIABLE_REQUIRED
FORMULA_ZERO_WEIGHTS
source_unavailable
source_incompatible
not_calculable
unmeasured
TRUSTED / trusted_no_gap_condition
```

## Lifecycle

Statuses:

```text
open
acknowledged
in_treatment
verified
closed
```

Valid transitions are enforced in `grcGap.service.js`.

Every creation, evaluation confirmation, reopen and manual transition is inserted into `grc_gap_status_history`.

`verified_at` and `resolved_at` are set only when semantically entering `verified` or `closed`. `first_seen` and `last_seen` derive from source Observation `observed_at`; no fake event date is generated.

## AI hypothesis separation

AI/non-deterministic signals are not deterministic Gap truth.

They can be stored only in:

```text
grc_gap_hypotheses
```

with `deterministic_gap=false`.

## Finding/Gap relationship strategy

Findings, readiness findings, nonconformities and action plans remain domain-specific or treatment models.

6.8-03 does not copy all findings into Gaps and does not query `findings` as a hidden Gap producer. A future finding-derived Gap must be explicit, rule-governed and provenance-linked.

## Provenance and relation

Gap metadata preserves:

- source Observation id/type
- source identity hash
- source snapshot id when present
- source `observed_at`
- rule code/version
- Data Trust metadata
- deterministic identity payload
- correlation id

Observation -> Gap relation is persisted in:

```text
grc_observation_relations
related_entity_type = grc_gap
relation_type = supports
```

No `grc_observation_links` runtime dependency exists.
