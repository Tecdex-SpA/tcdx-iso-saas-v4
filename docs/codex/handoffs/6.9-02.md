## Decisión arquitectónica

Impact Graph 2.0 queda como capa de adapters/proyección:

```text
DOMAIN SOURCES OF TRUTH
  -> DOMAIN ADAPTERS
  -> CANONICAL GRAPH PROJECTION
  -> SERVICE/API CONSUMERS
```

No se creó migración, tabla `grc_graph_edges`, graph database ni materialización paralela. Las fuentes de dominio siguen siendo la verdad.

## Contrato implementado

Archivo principal:

- `backend/src/services/grc/impactGraph.service.js`

Contrato conceptual materializado:

- `GraphNode`: identidad determinística por `tenant_id + entity_type + entity_id`, metadata mínima.
- `GraphEdge`: identidad determinística por tenant, endpoints, relationship type, source model/record, derivation rule y persisted/derived.
- `GraphProjection`: `model_version`, seed, nodes, edges, limits, depth y `projected_at`.
- `GraphProvenance`: source domain/model/record, source tenant, relationship type, owner, persisted/derived e inputs de derivación.

`model_version = impact-graph-2-foundation-v1`.

## Adapters implementados

| Adapter | Source of truth | Semantics |
|---|---|---|
| `requirement_control_mapping` | `grc_requirement_control_mappings` | Requirement -> tenant/catalog control, persisted |
| `evidence_entity_link` | `grc_evidence_links` | Evidence -> GRC entity, persisted |
| `generic_phase2_relation` | `grc_phase2_relations` | Controlled cross-domain relation, persisted, confidence when present |
| `operational_dependency` | `grc_operational_dependencies` | Process/service dependency, persisted |
| `process_entity_link` | `tenant_process_entity_links` | Process -> control/evidence/risk/action, persisted |
| `canonical_observation_relation` | `grc_observation_relations` | Observation -> related entity including Gap, persisted |
| `gap_derivation` | `grc_gaps` | Observation -> Gap derivation metadata, derived projection |

## Service/API surface

Integrated through existing GRC facade:

- `GET /api/grc/impact-graph/nodes/:entityType/:id/relationships`
- `GET /api/grc/impact-graph/neighborhood/:entityType/:id`

Routes use existing GRC route authorization and service permission `workflow.read`. No new RBAC permission or migration was added.

## Tenant, temporal and provenance semantics

- Every adapter query is tenant-scoped.
- Mixed global/template requirement mappings are projected under the requesting tenant while preserving `source_tenant_id=null` in provenance.
- No cross-tenant fallback or cache exists.
- Empty tenant returns a valid projection with the seed node and no edges.
- Temporal fields preserve domain source semantics: `created_at`, `valid_from`, `valid_to`, `valid_until`, `first_seen`, `last_seen`.
- `projected_at` is technical evaluation time and is not part of node/edge identity.
- Confidence is emitted only for sources that physically support it (`grc_phase2_relations`, `grc_observation_relations`).

## Observation / Gap behavior

- Observation relations consume `grc_observation_relations`.
- Observation -> Gap canonical persisted edge uses `relation_type='supports'` from `grc_observation_relations`.
- Gap derivation is projected from `grc_gaps` as `persisted_or_derived='derived'` with derivation rule provenance.
- No `grc_observation_links` dependency was introduced.

## Traversal safeguards

- `depth` capped at `3`.
- `max_nodes` capped at `100`.
- `max_edges` capped at `200`.
- Traversal reads adapters per frontier level, deduplicates by deterministic edge id and stops at caps.
- No graph centrality, shortest path, recursive SQL or future Priority Engine scope was implemented.
