## Root Cause

`ROOT_CAUSE_TIMESTAMP_SERIALIZATION = PASS`

Runtime evidence showed eligible outbox events were created correctly, but canonical Observation persistence failed with PostgreSQL `22007` because a JavaScript `Date` was serialized as:

```text
Tue Aug 18 2026 16:51:19 GMT+0000 (Coordinated Universal Time)
```

Exact type flow:

| Field | Source type | Intermediate type | Serialization point | Final bind |
|---|---|---|---|---|
| `observed_at` | `grc_observation_emission_outbox.observed_at timestamptz` | PostgreSQL driver returns `Date` in `processOutboxEvent()` | `observationBodyFromEvent()` passed the `Date`; Semantic Layer `text()` converted it with `String(Date)` | `$11::timestamptz` in `semanticLayer.createManualObservation` received invalid Date string |
| `period_start` | `grc_observation_emission_outbox.period_start timestamptz` | PostgreSQL driver returns `Date` when non-null | Boundary previously passed raw value to Semantic Layer | Now normalized before boundary |
| `period_end` | `grc_observation_emission_outbox.period_end timestamptz` | PostgreSQL driver returns `Date` when non-null | Boundary previously passed raw value to Semantic Layer | Now normalized before boundary |

## Fix

- Added local timestamp normalization in `backend/src/services/grc/grcObservationEmitter.service.js`.
- Outbox event construction accepts `Date` by converting it to ISO while preserving already-valid strings to avoid unnecessary idempotency drift.
- The service boundary into `semanticLayer.createManualObservation` now always sends:
  - `observed_at`: ISO-8601 UTC string, required.
  - `period_start`: ISO-8601 UTC string or `null`.
  - `period_end`: ISO-8601 UTC string or `null`.
- Missing/invalid `observed_at` is not replaced with `now()`.
- Optional null periods remain null.
- No migration was created.

## Retry

Existing failed events must not be deleted or edited manually. The existing outbox worker supports retry through:

- `defaultService.processNextPending(scope)` for the next `pending`/`failed` event with `next_attempt_at <= now()`.
- `processOutboxEvent(scope, eventId)` for targeted retry when invoked through an approved operational Node context with the correct tenant scope.

Do not update `attempts`, `next_attempt_at`, `status` or `last_error` manually in production.
