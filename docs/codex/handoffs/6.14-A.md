## AI Governance Behavior

`aiGovernance.service.js` defines a registry for real AI-capable surfaces:

- `intelligence_narrative`
- `knowledge_rag_answer`
- `cross_grc_intelligence`
- `operational_learning`

Each capability declares provider/model strategy, prompt contract, context contract, output schema, policy version, authority boundary, allowed tools, grounding requirements, tenant/private/global/regulatory data use, external lookup boundary, human review requirements, failure semantics and retention/redaction rules.

`intelligence.ai-orchestrator.js` now attaches governed trace metadata to existing AI prompt logs without changing the orchestrator ownership or creating a second AI orchestrator.

## Authority Boundaries

Required zero-authority gates are explicit in policy:

```text
LLM_DIRECT_SQL = 0
AI_OPERATIONAL_TRUTH_AUTHORITY = 0
AI_COMPLIANCE_FINAL_AUTHORITY = 0
AI_RISK_ACCEPTANCE_AUTHORITY = 0
AI_GAP_CLOSE_AUTHORITY = 0
AI_LEGAL_PUBLISH_AUTHORITY = 0
AI_DECISION_AUTHORITY = 0
AI_OPERATIONAL_MEMORY_PUBLISH_AUTHORITY = 0
```

Retrieved documents, tenant documents and external web content are evidence only, not instructions. They cannot grant permissions, alter system policy, execute tools, write SQL, publish legal/operational truth or approve decisions.

## Failure Semantics

Governed status set:

```text
success
fallback
insufficient_evidence
provider_unavailable
timeout
invalid_output
policy_blocked
grounding_failed
dependency_unavailable
```

Provider errors do not become successful responses. Existing deterministic fallback remains preserved.

## AI Evaluation Suite

`aiEvaluationSuite.service.js` provides synthetic/non-private golden cases with stable identities and governed expectations. It validates structure/facts instead of exact narrative text.

Covered dimensions:

- structured output validity
- grounding/citation precision
- factual support
- insufficient-evidence behavior
- hallucination/fabricated citation guard
- prompt-injection resistance
- policy/authority boundary
- tenant isolation
- deterministic fallback semantics
- provenance completeness
- regression comparison between baseline and candidate versions

Result statuses: `PASS`, `FAIL`, `NOT_APPLICABLE`, `INSUFFICIENT_FIXTURE`.
