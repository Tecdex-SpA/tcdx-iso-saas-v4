## Data Model

### Authoritative Source Registry

Table: `regulatory_authoritative_sources`

Contract: `authoritative-source-registry-v1`

Represents governed official sources with:

- `source_key`, `scope`, `tenant_id`
- `authority_classification`
- `authority_type`, `jurisdiction`, `country_region`
- `issuing_authority`, `official_name`, `stable_identifier`
- `official_domain`, `official_source_uri`
- `allowed_ingestion_method`, `status`, effective range
- metadata/provenance/health

Scope rules:

- `GLOBAL` and `JURISDICTIONAL`: `tenant_id IS NULL`.
- `TENANT_PRIVATE`: `tenant_id IS NOT NULL`.

Only `AUTHORITATIVE` + `active` sources can create canonical regulatory truth.

### Regulatory Ingestion

Table: `regulatory_ingestions`

Contract: `regulatory-ingestion-contract-v1`

Each ingestion stores source, `knowledge_document_id`, official identifier, version identifier, URI/reference, original/extracted/content checksums, acquisition/publication/effective timestamps, parser/extraction method, actor/correlation and provenance.

Ingestion is immutable by version/checksum. New official publication creates a new `knowledge_documents` row and a new `regulation_versions` row; `updated_at` is not version identity.

### Knowledge Integration

- Regulatory document envelope: `knowledge_documents(scope='REGULATORY', tenant_id=NULL, source_authority='authoritative')`.
- Regulatory chunks: `knowledge_document_chunks(scope='REGULATORY', tenant_id=NULL)`.
- No `regulatory_documents_v2`.
- No `regulatory_chunks`.
- No second KB or second embedding model.

### Regulation

Table: `regulations`

Contract: `regulation-model-v1`

Stable legal/regulatory identity by normalized `(scope, tenant_id, regulation_key)`, jurisdiction, source, issuer, official identifier/title/type and lifecycle.

### RegulationVersion

Table: `regulation_versions`

Contract: `regulation-version-model-v1`

Immutable publication/version tied to `regulations`, `regulatory_ingestions`, `knowledge_documents`, checksum and supersession lineage.

### LegalObligation

Table: `legal_obligations`

Contract: `legal-obligation-model-v1`

Explicit governed obligation tied to regulation/version, reference, text checksum, subject/action/applicability/effective range, optional source chunk and provenance.

AI may suggest future candidates, but cannot publish legal obligations.

## Tenant Semantics

- Public regulatory truth uses `GLOBAL`/`JURISDICTIONAL` rows with `tenant_id=NULL`.
- Tenant-private regulatory/reference sources remain `TENANT_PRIVATE` and tenant-scoped.
- Service listings show public sources/regulations plus same-tenant private rows only.
- Body `tenant_id` is not authority for public regulatory scope.
- Tests cover tenant A private source visibility, tenant B exclusion and empty tenant behavior.
