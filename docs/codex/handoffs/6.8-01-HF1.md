## Migration strategy

Decision: C) both.

- Correct `20260818_f6_8_01_grc_observation_model.sql` because it may not be universally applied and must not define the wrong model.
- Add `20260818_f6_8_01_hf1_observation_reconciliation.sql` because some environments may have partially applied the wrong migration.

Migration changes:

- No redefinition of `grc_observations`.
- No creation of parallel relation persistence.
- No mutable updated-at trigger on canonical observations.
- Add canonical indexes on `status_value`, `severity_value`, and `source_table/source_record_id`.
- Bootstrap global semantic contract `grc.manual_observations` v1 for manual API provenance in the corrected historical 6.8-01 migration for fresh installs.
- HF2 follow-up required for deployed installs: `database/migrations/20260818_f6_8_01_hf2_manual_observation_contract_bootstrap.sql` is the forward runtime bootstrap tracked in `schema_migrations`.
- HF1 migrates rows from the deprecated relation table to `grc_observation_relations`, preserving original relation/source metadata, then removes the deprecated table.
- HF1 drops `trg_grc_observations_touch_updated_at` and `grc_touch_observation_updated_at()` if present.
- HF1 refuses unsafe reconciliation if `grc_observations.source_identity_hash` is absent.
