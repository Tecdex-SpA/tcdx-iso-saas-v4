## Canonical model decision

HF1 supersedes the original Option C. Discovery found the adequate transversal model already existed in the Phase 5-C2 Semantic Layer. Final canonical model:

- `grc_observations`
- `grc_observation_relations`

## RBAC

Uses the existing GRC `authorized(...)` pattern and permission table:

- read: `observation.read`

No new RBAC engine was created.

## Tenant isolation

All observation, source and relation operations validate `tenant_id`. A source from another tenant cannot be linked to or used by an observation. A tenant with no observations receives an empty list.

## Provenance

Canonical provenance fields:

- `contract_id`
- `contract_version_id`
- `source_table`
- `source_record_id`
- `source_identity_hash`
- `source_snapshot_id`
- `correlation_id`
- `metadata`
- `data_lineage_edges`

Manual API observations use the global semantic contract `grc.manual_observations` and `data_snapshots`; non-manual API observations validate the source id in the same tenant before canonical persistence.

## Relations strategy

`grc_observation_relations` provides the minimal canonical relation foundation for targets such as audit, control, risk, requirement, evidence, action, incident, assessment and document. HTTP `/links` remains an API projection only. Full graph semantics remain for F6.9.
